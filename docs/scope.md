# Scope ledger

**This file is the record of intent. The code is the record of delivery. This file exists so the
gap between them is never a matter of memory.**

The intent is set by two documents, and this ledger is subordinate to both:

- `Thin Film Design Software - Merit Function Specification.md` — the merit subsystem, its operands,
  aggregation, configurations, sampling and phasing. **The authority on what the program must do.**
- `abi-and-allocation-contract.md` — how C# and C++ divide memory and responsibility.

## States

| | meaning | rule |
|---|---|---|
| **BUILT** | implemented and tested; the test is named | — |
| **REFUSES** | not implemented, but the ABI can express the request, so a named symbol refuses loudly with a named status code | `test_scope` asserts it still refuses |
| **NO SEAT** | the ABI cannot express the request at all, so there is nothing to refuse. The gap is in the ABI, not the implementation | **must reach zero before the ABI is frozen** |
| **ABOVE ABI** | sits above the native boundary; nothing can reach it and nothing needs to refuse | only legitimate outside native |

**The `NO SEAT` rule is the one that protected the project.** A feature with no seat is a feature
that will force an ABI break and a rewrite of everything bound to it, so `ABI_FROZEN` at the foot of
this file was held at `no` until the count reached zero and
`tools/check-constraints.cmake` failed the build on any attempt to set it otherwise. The count
reached zero at S6.4 and **the ABI is now frozen**; the rule stays here because it still governs
anything that would reopen it.

There is no state for "half built". An item that is neither built nor refusing nor seatless is the
failure mode this ledger exists to catch.

## Why the derivatives come first

**This project is a derivative engine that happens to compute spectra.** That was said in the
original request — *"I expect a mixture of automatic derivatives and analytical (derived)
derivatives"* — and the specification says it again from the other direction: the gradient section
*"drives the operand interface design and should be settled before any operand is written,"* because
retrofitting `P(z)` later *"means touching every operand."*

So the derivative table below is section 1, and it is the section that sets the order of all the
work. Three consequences follow, and they are not stylistic:

1. **The operand interface cannot be designed first.** An operand's return contract is value,
   residual, gradient and `P(z)`. Until the engine can produce each of those and their cost is
   known, any operand ABI is a guess.
2. **Every derivative is analytic unless something says otherwise, loudly** (C0.7). The one
   sanctioned exception is the Phase 3 scripting hook, which must label its finite differences as
   such.
3. **Every derivative is verified against central differences of a trusted evaluator, on absorbing
   stacks and at high AOI** — the spec names those two conditions because that is where sign and
   branch errors hide. `test_jacobian` already does this for ∂/∂d and is the template for the rest.

Section ids (`D2.1`, `S1.4`, …) are stable identifiers referenced by commits and tests. They do not
track section numbers and are not renumbered when sections move.

## 1. Derivatives — the heart of the project

Every derivative the program uses is BUILT and checked against differences, absorbing layers and
high angles included (D2.8). They came first because they were unblocked - they depend on the
stack and the materials, not on the operand model, the configuration model or the grids - and
because everything else was blocked on them. **None of the refusals below can be reached from the
GUI, the CLI or MCP** (reviewed 2026-10-25): D2.5 would serve a feature the program does not have,
D2.9c a configuration it never builds, and D2.9d and D2.6 are deliberate.

| id | item | state | note |
|---|---|---|---|
| D2.1 | ∂v/∂dᵢ — layer thickness | **BUILT** | `tf_jacobian.cpp`; reverse sweep, n parameters |
| D2.2 | **P(z) — the needle perturbation function** | **BUILT** | *"Needle optimization and gradual evolution are the algorithms that make thin film synthesis work… retrofitting it later means touching every operand."* `tf_needle.cpp`. A layer splits as `M_j(d) = M_j(t)·M_j(d−t)`, so `P(z) = prefix[j]·M_j(t)·G_m·M_j(d−t)·S` with `G_m` the insertion generator; the backward sweep already holds `prefix[j]` and `S` together. Checked against **two independent oracles**: self-insertion equals growing the layer (exact, vs `tf_evaluate_jacobian`, 3.6e-14 over 30 depths) and a foreign material against a physically split stack (6.1e-9). Refuses on an opaque layer — see S6.3 |
| D2.3 | **∂/∂λ — the wavelength derivative** | **BUILT** | `tf_spectral.cpp`, verified against central differences that move n(λ) with λ, on four fixtures isolating each term - non-dispersive, dispersive, **immersed and oblique** (the only one that exercises `u' = 2n₀n₀'sin²θ₀`), and absorbing at 60°. Agreement 5.6e-14 to 6.7e-12. **Forward accumulation, no scratch at all**: one parameter, so carrying `(P, A)` with `A ← AM + P·dM` beats the reverse sweep. needed in **Phase 1**, not Phase 2: `LEDGE`, `SLOPE`, `CWL`, `BW` take their derivative by the implicit function theorem, `∂λₑ/∂dᵢ = −(∂T/∂dᵢ)/(∂T/∂λ)`. Spec §Requirements forbids finite-differencing it — half the significant digits per order, and TOD becomes unusable in double |
| D2.4 | ∂v/∂n and ∂v/∂k — index | **BUILT** | `tf_index_derivative.cpp`. Per MATERIAL, summed over every layer made of it, at the wavelength of each residual. Reverse sweep accumulated per material. Two real derivatives from one complex sweep, since `dN/dn = 1` and `dN/dk = −i`. Checked against Richardson-extrapolated differences and **two exact identities**: `dR/dn + dT/dn = 0` for a lossless stack (1e-12) and splitting a material in two sums to the combined derivative (1e-13). **This is the optics half of the analytic/autodiff seam**: `dv/dc = dv/dn · dn/dc`, and the right factor is the material model's job |
| D2.5 | Automatic differentiation through dispersion models | **NOT NEEDED** by anything built (reviewed 2026-10-25) | No longer blocked: the dispersion models are BUILT, above the ABI (M3.1). What it would give is `dn/dc`, the derivative with respect to a material's coefficients, and nothing varies those - a design's materials are data, not variables, and the engine refuses a material-coefficient variable with `TF_NOT_IMPLEMENTED_VARIABLE`. It would be needed to **fit a material to a measured spectrum**, which is not a feature. The optics half (D2.4) is done; `TF_NOT_IMPLEMENTED_DISPERSION` (68) stays reserved and is never raised |
| D2.6 | Second-order ∂² | not required in the first release | spec says so explicitly |
| D2.7 | Needle-capability declared per operand | **ABOVE ABI** — contract §7: the managed stage drops the operands that cannot supply `P(z)` and tells the user which it dropped. Native never silently optimises a subset of what it was handed |
| D2.9c | A needle map over a REVERSED configuration | **REFUSES** — `TF_NOT_IMPLEMENTED_REVERSED` (72). A depth is "from the front of the stack", and which side that is under reversal is a question: the physical front (one map shared by both directions) or the illuminated side (what a user of one configuration expects). The two differ silently. **Unreachable from the program** (reviewed 2026-10-25): the managed side never builds a reversed configuration - Reverse layers and media reverses the stack itself - so no needle run can meet this refusal |
| D2.9b | **3a-ii** — spans and the operand DAG through the other derivative entry points | **BUILT** for `tf_evaluate_needle` and `tf_evaluate_index_derivative`. `tf_operand_pass` walks the DAG once for every entry point and `tf_operand_adjoint` gives the reverse chain the needle map wants, so a reduction is not special to any one of them |
| D2.9d | `d/dλ` of a multi-wavelength operand | **REFUSES** — and this one is a DEFINITION, not a gap. A band average over forty samples has no single wavelength: shifting every sample rigidly and moving one are different numbers, and nothing can tell which was meant. The call exists for group delay, which is pointwise, and step 3b showed `CROSSING` never needed it. The refusal stands until something asks for a spectral shift and says which kind |
| D2.8 | Every derivative exercised against finite differences, **with absorbing layers and at high AOI** | **BUILT** for D2.1 to D2.4 (reviewed 2026-10-25) | spec §Implementation. `test_jacobian` (thickness), `test_spectral` (∂/∂λ, absorbing at 60°), `test_index_derivative` (∂/∂n, ∂/∂k, an absorbing high index at 40°, Richardson differences) and `test_needle` (P(z) at 0° and 50°, against two exact oracles). The needle test had an absorbing case written but never run; it is run now: k = 0.02 at 50°, 30 depths, worst relative error 1.3e-14 |

Four is the ratio of the *matrix arithmetic*; the transcendentals are shared by both paths and do not halve with the matrix. The prize is still real — the sweep is **85%** of a Jacobian, a Jacobian would gain **1.66×**, and a refinement spends **76%** of its time in Jacobians, so a run gets **~30% shorter**. | S1.11 | Normal-incidence degeneracy: at θ=0, s and p are one solve | not built, **ceiling measured**; **planned for a later release** (the user, 2026-10-25) | X1.5: asking for both polarisations costs **2.03×** asking for one, on the same stack at the same angle, so that ratio is the ceiling on what this could return at θ=0. It halves the commonest AR case. Changes results in the last ulp, so it is a decision, not a free win |
| S1.12 | **`TF_PLAN_STALE` is declared and never raised** | not built — found by X1.2 | `tf_status` reserves code 5 for "the problem changed shape since tf_plan ran", and nothing in `native/` raises it. So nothing refuses an evaluation against a plan whose assumptions have expired, and they *can*: `tf_plan` picks a path per point partly from thickness — a layer thick enough to absorb everything clamps — and marks variables inert on the same grounds. An optimiser that drives a layer opaque has changed a plan input without changing any count. **Not an ABI question** (the code is already reserved, so building it changes behaviour behind a symbol that exists) and not a refusal, because the answer is right until it is not. | S1.13 | **The plan's scratch size must serve every entry point** | **BUILT** — found by X1.4 | `tf_scratch_doubles_for` sized two of its terms for the Jacobian alone: the needle map wants two doubles per operand where the Jacobian wants `n_variables`, and two per slot where it wants one. With three or more variables the Jacobian's term happened to cover it, so every native needle fixture passed — they all have six variables. A single-layer AR coating has one, and the needle map refused it with `TF_SCRATCH_TOO_SMALL` the first time the optimiser did the obvious thing: refine one layer, then ask where the next should go. One scratch serves five entry points, so every term is now the maximum over them. `TheScratchThePlanAsksForIsEnoughForANeedleMap` in `test_needle` allocates exactly what the plan asks and pins it |
| S1.14 | **Group delay and GDD operands** | **BUILT** (ABI 11), 2026-10-20 — found by X1.6 | the user, on the chirped-mirror sample: *"Why is chirped mirror incomplete? What do we need to do?"*, then *"Yes"*. `TF_TARGET_R_GD_S` … `TF_TARGET_T_GDD_P`: GD = dφ/dω in fs and GDD = d²φ/dω² in fs², reflection and transmission, s and p, positive for a delay. Analytic throughout (`tf_dispersion.cpp`): the first and second wavelength derivatives of the amplitudes are carried through the characteristic matrix as jets, and the thickness Jacobian is the prefix/suffix scheme applied to the jets, so nothing is differenced and no phase is unwrapped. GDD needs d²n/dλ², which ABI 11 adds; the API sends both derivatives from each material's model (analytic for Cauchy and Sellmeier, the segment slope for a table, a central difference for a catalogue glass) only when a GD or GDD row is present. Checked: an air gap adds exactly 2L/c; GD against the phase's slope and GDD against GD's, dispersive, absorbing, immersed and oblique; the Jacobian against differences in thickness; refusals without the data. The chirped-mirror sample now asks for GDD = −50 fs² from 750 to 850 nm, and refinement takes its mean miss from about 45 to under 10 fs² with Rs above 99%. Not done: TOD, the GDD ripple operands (GDDC, GDDOSC), configurations, and the needle map, wavelength and index derivatives, which refuse a table with these codes |
| S1.15 | **DLS reported `Converged` when it was stalled** | **BUILT** — found by X1.6 | the stopping test was relative merit improvement alone, which goes small at a minimum AND at a point where the damping has grown so large that every step is tiny. Those are opposite situations and it called both convergence: on the V-coat template it reported `Converged` after moving the merit 453 to 446 with **`|Jᵀr|` ending higher than it started**. Found by asking every template to end stationary. The solver now tracks `|Jᵀr|` and distinguishes `Converged` from a new `Stalled` outcome by it, so the claim is checkable — and the template suite checks it, on the solver's own relative criterion |
| S1.16 | **Bounds did not follow a change of shape** | **BUILT** — found by X1.7 | a needle insertion adds variables and a removal drops them, but `DampedLeastSquares` indexed `options.Lower[i]` by its own variable count without checking the array described that many. With bounds set and a needle run, it read past the end — an `IndexOutOfRangeException` thrown from a constructor, which is the least informative way a shape mismatch can present itself. X1.4's needle tests passed no bounds and X1.6's template tests ran only `refine`, so it took the API running `needle` **with** bounds to reach it. The solver now refuses a mismatched bounds array **by name**, and `Bounds.For` rebuilds them with the shape — a new layer taking the loosest bound the caller already permitted, since it has none of its own |
| S1.17 | **Third-order dispersion (TOD) operands** | **BUILT** (ABI 12), 2026-10-23 | the user: *"I did want to return to TOD"*. `TF_TARGET_R_TOD_S` … `TF_TARGET_T_TOD_P`: TOD = d³φ/dω³ in fs³, reflection and transmission, s and p, with the sign of GD and GDD. `tf_dispersion.cpp` was rewritten for it: every quantity that moves with wavelength is a truncated Taylor series to third order, and products, quotients, square roots, sines and cosines of series are the exact recurrences, so GD, GDD and TOD come out of one path with no hand-expanded derivatives, and a higher coefficient never feeds a lower one. The rewrite reproduces every GD and GDD check of S1.14 unchanged. TOD needs d³n/dλ³, which ABI 12 adds; the API sends it from each material's model (analytic for Cauchy and Sellmeier, zero for a linearly interpolated table, a central difference for a catalogue glass) only when a TOD row is present. Checked: an air gap adds no TOD; TOD against a central difference of GDD, dispersive, absorbing, immersed and oblique; the Jacobian against differences in thickness; the needle map against inserting a needle; refusal without d³n/dλ³, and GD and GDD unchanged to the bit without it |

## 3. The operand model — BUILT, whole subsystem

The ABI has a flat list of target codes. The spec has an *operand*, and the difference is not
cosmetic: comparison type and tolerance change what a residual **is**.

| id | item | state |
|---|---|---|
| O3.1 | Comparison type `=`, `<=`, `>=`, `range`, contributing **exactly zero with zero gradient** when satisfied | **BUILT** — `tf_comparison`, `tf_score_of`; `test_comparison`. The residual and its slope come from ONE function, because a zero residual paired with a non-zero slope is a gradient pointing away from a satisfied constraint and nothing downstream could detect it |
| O3.2 | Tolerance / deadband | **BUILT** — shrinks the error toward zero rather than clipping it, and takes the slope with it |
| O3.3 | Group reference and group weighting | **ABOVE ABI** — a group weight is a reweighting of a residual vector; contract §10.4 |
| O3.4 | Enabled flag | **ABOVE ABI** — managed drops the row before the call, so native never sees a dead operand; contract §8.4 |
| O3.5 | Per-operand normalisation scale | **BUILT** — `scale` divides the error and never reaches the merit denominator, so a weight still means only relative importance |
| O3.6 | Raw **and** normalised contribution both reported | **BUILT** — `tf_output.value` carries every operand's raw value, scored or not; the normalised contribution is its residual |
| O3.7 | Weight | **BUILT** | `operands.weight`, `sqrt(w)` convention measured from LensHH-LT |
| O3.8 | Cost tier per operand | **ABOVE ABI** — a property of the operand CODE, a compile-time fact, so it belongs in a managed table; contract §8.4 |

## 4. Aggregation

| id | item | state |
|---|---|---|
| A4.1 | L2, `√(Σwᵢrᵢ²/Σwᵢ)` | **BUILT** — and the spec's formula is exactly the one measured from LensHH-LT |
| A4.2 | L1 | **BUILT** — `Norms.cs`, IRLS reweighting of the returned residual vector, exactly as this row specified |
| A4.3 | **L∞ / minimax** | **BUILT** — `Norms.cs`. *"Minimax matters more here than in lens design."* Almost every coating spec reads `R < 0.5% across the band`, a Chebyshev statement, and an L2 fit will trade a uniform 0.4% for 0.1% almost everywhere and 0.9% at one wavelength. Reached by Lp continuation under IRLS. **The loop keeps the best pass, not the last**, which is what makes it work: each pass ends at the optimum of *its own* weighting, and returning that gave a worst case of 74 against plain L2's 47 at one p and 34 at another — the answer was moving with which local minimum the final weighting sat in, not with p. | A4.4 | Lp with p-continuation | **ABOVE ABI** — IRLS |
| A4.5 | Norm as a **per-stage** setting | **ABOVE ABI** — a stage picks its own weight rule |
| A4.6 | Robust norms — Huber, saturation | **ABOVE ABI** — IRLS |
| A4.7 | Residual, gradient and scalar exposed **separately** | **BUILT** — residual and Jacobian; gradient is `2Jᵀr`, one reduction away |

## 6. Spectral sampling — BUILT, and the spec calls it the commonest source of wrongness

*"A user specifies twenty targets across a band, the optimizer drives all twenty to zero, and the
design ripples wildly between them. The merit is excellent and the coating is useless."*

| id | item | state |
|---|---|---|
| G6.1 | **Evaluation grid separate from target grid** | **ABOVE ABI** — resolved by `evaluation-model-contract.md` §2 and §5: there is no target grid at the ABI. ## 7. Operands

Grouped by the spec's phases. The operand model now has a seat, so these rows are marked
individually: **BUILT** where the code answers, **REFUSES** where it refuses loudly and by number.

### Phase 1

| operand | note | state |
|---|---|---|
| `R`, `T` | front or back side selectable | **BUILT** as Rs/Rp/Ra/Ts/Tp/Ta; no side selection |
| `A` | **BUILT** — `TF_TARGET_AS/AP/AA`, its own code rather than `1−R−T` at the call site. Checked by the identity `A + R + T = 1`, gradients included |
| `OD` = −log₁₀T | **BUILT** — `TF_TARGET_ODS/ODP/ODA`, ceiling in `reduction_param[1]`. `ODA` is the OD of the average transmittance, **not** the average of two ODs: a filter blocking one polarisation and passing the other blocks nothing, and averaging in log space would report that it half-blocks. The default ceiling is derived from double precision (OD 16), not the spec's OD 8 — that is a statement about films rather than about doubles, so the caller makes it |
| `RAVG`, `TAVG`, `AAVG`, `ODAVG` | **BUILT** — a `SUM` span with the weighting in `point_weight` over the corresponding pointwise code. `ODAVG` averages `OD` operands, which IS log space |
| `PHR`, `PHT` | **BUILT** — `TF_TARGET_R_PHASE_S/P`, `T_PHASE_S/P`. Angles, so they obey `delta_convention` exactly as Δ does; there is deliberately no "average" variant, because averaging two angles is not an operation |
| `PSI`, `DEL` | ellipsometric | **BUILT** |
| `LEDGE`, `SEDGE`, `CWL` | **BUILT** — `TF_REDUCE_CROSSING`. Bracket on the sampled spectrum and interpolate; the derivative is the exact derivative of that interpolation, which IS the implicit function theorem and needs **no** D2.3 - a crossing does not land on a grid point and `material_index` is a table, so evaluating off-grid was never possible. `BW`, `SLOPE` and `SHAPE` are differences and ratios of these, so they are `TF_TARGET_DIFFERENCE` and `TF_TARGET_RATIO` over two crossings |
| `RIPPV`, `RIPRMS`, `TMAX`, `TMIN`, `ODMIN` | **BUILT** — `PTV`, `RMS_DEV`, `MAX`, `MIN` reductions, with the smooth-extremum sharpness in `reduction_param[0]`. `ODMIN` is `MIN` over `OD` operands |
| `DEDGE` | two configurations | **BUILT** — a `TF_TARGET_DIFFERENCE` over two `CROSSING` operands in different configurations |
| `TSP`, `RSP`, `EXTT`, `EXTR`, `DIAT` | **BUILT** — the plain ratios are `TF_TARGET_RATIO` over two operands; the decibel and normalised-difference forms have their own codes, because a logarithm is not a ratio |

Shipped separately from a pair of Rs/Rp targets for the reason the spec gives: as a difference it has a well-conditioned gradient toward balance, where two independent targets fight and converge on a compromise satisfying neither. The kink at balance takes subgradient ZERO, the same choice as a comparison exactly on its limit |
| `MINT`, `MAXT`, `TOTT`, `NLAY` | penalties, **not only hard bounds** — a bound stops the optimizer at a wall with no gradient; a penalty gives direction before it arrives | **BUILT** — `TF_TARGET_TOTT/NLAY/MINT/MAXT` (86–89), threshold in `reduction_param[0]`. A **third operand kind**: reads `layer_thickness`, owns no points, and `tf_slot_count` returns 0 for it, so it never claims a point slot. `TOTT` and the two hinges have exact derivatives (`1`, `±1`, `0`); `NLAY` is constant under every continuous variable and moves for nothing. They also make an **optically dead layer live** — a variable an optical operand cannot see is still live when its thickness is being scored. **`MINT` reaches the needle map with exactly zero, and that is not an omission**: a needle is inserted at zero thickness, so it is born in full violation and `MINT`'s slope there is `−1` — feeding that in would make every insertion look a constant amount *cheaper*, the opposite of the operand's purpose. `MINT`'s discouragement is a **step** at ε=0⁺, and a first-order map cannot represent a step; it belongs to the discrete accept/reject stage. `TOTT` does reach the map, because adding ε genuinely adds ε |

**Failure modes that must be explicit, not sentinels** (spec §Extraction): no crossing in the search
band returns a large penalty proportional to distance from the nearest attained level, with a
gradient pushing toward a crossing; multiple crossings report ambiguity and take the one nearest the
previous iteration, so the operand does not jump between optimizer steps.

**Rule for X1.1–X1.3: no physics in C#.** The wrapper allocates, pins, calls and marshals. A number
computed in managed code that could have been computed in native is a defect — a second
implementation that will diverge. X1.3 is how that is caught.

**X1.1 found a native bug, which is what a wrapper is for.** `tf_query_plan_sizes` sized
`point_span_operand` and `point_span_slot` by `n_span`, but those buffers hold one entry per
**slot** — which is `n_span` in span mode and `n_operands` in pointwise mode, where `n_span` is
zero. A caller that allocated exactly what it was told handed `tf_plan` two zero-length buffers
and the transpose wrote past both. No native test saw it, because several of them pass
`n_operands` as the `n_span` argument and over-allocate into the right answer by accident; the
binding had no such habit, asked the way the ABI says to, and got an access violation. C0.1 puts
allocation on the caller, so a wrong size here is not a detail — it is memory corruption in
somebody else's process, and the one mistake the caller cannot defend against. Fixed in
`tf_query_plan_sizes`, with `TheSizeQueryIsEnoughOnItsOwn` in `test_plan` allocating exactly the
returned sizes and checking a canary. **No layout changed, so the freeze is intact** and no
version bump was needed: the fix only ever returns a larger number, so no caller can be broken by
it.

## The ABI is frozen

    ABI_FROZEN: yes

**Frozen at `TF_ABI_VERSION 9`**, with zero `NO SEAT` rows outstanding. Every field, code and
status number in `thinfilm.h` is now something C# may bind to, and changing any of them stops
being an edit and becomes a version bump with a migration.

### What enforces it

A flag in a document is a promise. Three things make it a mechanism:

- **`tests/native/test_abi_frozen.cpp`** pins every struct size, every field offset and every
  enumerator value to the number it had at the freeze — 249 checks. Those are exactly the numbers
  a P/Invoke layout is computed from, which is why a *layout* change is the one that must fail
  loudly: insert a field in the middle of `tf_problem` and nothing in C++ breaks, because the C++
  is recompiled, while every managed caller silently reads the wrong bytes. The pins were checked
  against three deliberate breaks — a field inserted mid-struct (19 failures), **a field appended
  to the end (2)** and an enumerator renumbered (1). The appended-field case is the one worth
  naming: it is harmless for C++ and it is not harmless for a managed struct compiled against the
  old size, so it is the change most likely to be waved through.
- **`tools/check-constraints.cmake`** still refuses a frozen ABI while any `NO SEAT` row exists,
  so reopening the ledger and leaving the flag set fails the build.
- **The change log below** must carry a row for whatever `TF_ABI_VERSION` says. A bump without a
  row, or a row without a bump, fails the same check.

The three are deliberately inseparable: a real ABI change has to move the header, the pins and the
change log in one commit, and there is no order in which two of the three pass alone.

### What was checked before freezing

A freeze is only as good as the last thing nobody looked at.

- Everything the specification called architectural is done — **D2.2** (needle `P(z)`), **D2.3**
  (∂/∂λ), **G6.1** (evaluation grid separate from target grid), and the operand model those were
  blocked behind.
- The three kinds of question a seat can fail to answer are each closed by a different step. The
  **shape** question — what kinds of thing an operand may be — closed with the stack operands.
  The **content** question — what a material may carry — closed with M3.4. The **index** question
  — what a point *is* — closed with S6.4, and it was left for last because it is the only one that
  changes the meaning of an existing number rather than adding a new one.
- **M3.1, M3.2 and D2.5 do NOT need a seat**, and this is the row most likely to be mistaken for
  one. A dispersion coefficient as a variable looks like it needs `dn/dc` in `tf_problem`. It does
  not: the chain is `dv/dc = dv/dn · dn/dc`, the engine returns the left factor through
  `tf_evaluate_index_derivative`, and the right factor belongs to the material model above the
  ABI. So `TF_VARIABLE_MATERIAL_COEFFICIENT` being refused natively is a **definition** — the
  seam where analytic hands over to automatic — and not a gap waiting on a field.

The `REFUSES` rows that remain are implementation, not ABI: each one has its number reserved and
its seat already cut, so building any of them changes behaviour behind a symbol that already
exists rather than changing the shape of anything.

### What is now unblocked

X1.1–X1.10. The C# layer stops being premature — that was the whole point of the gate, so that
"the ABI is ready" would be a measured statement rather than an impatient one. **X1.1**
(`ThinFilm.Native`: P/Invoke, blittable structs, pinning) is the first row, and the pins above are
what its struct declarations must agree with.
